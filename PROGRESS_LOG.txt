LUDO PARTY - PROGRESS LOG
=========================

[Step 1] Rules engine and tests - COMPLETED
- Built the pure rules engine in shared/engine.js (createGame, roll, move, legalMoves,
  applyEvents) with constants and board math in shared/rules.js. No I/O; dice values are
  injected by the caller.
- server/game.js wraps the shared engine and adds server-side dice via crypto.randomInt.
- Implemented: enter on 6, bonus roll on 6/capture/home, three-sixes forfeit, captures,
  safe start and star squares, exact finish, auto-pass when no move exists, ranked finishing
  order, inactive (empty) seats, quick mode (1 or 2 tokens), blockades, capture-required-to-
  enter-home (tokens lap again), team mode (no teammate captures, stacking), assist mode.
- Tests: 20 node:test cases in tests/game.test.js, all passing, including randomized full
  games for 4/6/8 players in FFA and team mode, and event replay for client mirroring.
- Note: home column progress is numbered 13n..13n+4 with home at 13n+5 (progress 13n-1 is
  reserved for tokens that must lap again under the capture-to-enter-home rule).

[Step 2] Board generator and static render - COMPLETED
- shared/geometry.js: one parametric buildBoard(n) for 4/6/8 arms. Center is a regular
  n-gon (side 3); each arm is a 3x6 strip; yards are right-angle kites between arms so the
  outline is a clean square / hexagon / octagon. Outputs {x, y, rot} for 13n track squares,
  n x 5 home-column squares, 4 yard slots per seat, home slots and center triangles.
- client/js/board/render.js: DPR-aware BoardView with cached board layer (redrawn only on
  view change), cartoon pawns with highlight/outline/colorblind symbol, stacked-token fan-out
  with count badges, pinch-zoom/pan/wheel zoom and animated focus for 6/8-player boards.
- Classic look: white board, saturated yards with white inner squares and slots, colored
  start squares with white stars, grey star safe squares, colored home-entry arrows, colored
  home columns, center split into n colored triangles, soft board drop shadow.
- client/dev/boards.html shows all three boards side by side for review.
- Tests: tests/geometry.test.js (18 cases) - square counts 52/78/104, adjacency, no overlaps,
  home-column continuity, start squares beside own yard, yard slots inside outline.
- Fixed: star paths were missing beginPath, which recolored earlier stars and arrows.

[Step 3] Solo mode vs bots - COMPLETED

- client/js/local.js: LocalGame driver running the shared engine offline with crypto dice,

- client/js/ui/game.js: game screen with ordered event animation queue (fast-forwards when

- Home, solo/team setup (count, color, difficulty, rules), results podium, settings screens,

[Step 5] Online multiplayer server and client - COMPLETED
- server/index.js: one Node process serves the static client (/, /r/CODE, /shared) and the

  dual-stack (IPv4 + IPv6) by default.

- Turn timer (off / 15 s / 30 s) with server-side auto-play on timeout; three timeouts mark a
  player AFK and a bot plays until they interact. Server delays bots and timers until clients
  have finished animating. Spectators can join a running game. Quick chat (fixed phrases and
  emojis only), per-connection rate limiting, empty rooms cleaned up after 5 minutes.
- client/js/net.js (auto-reconnect with backoff, message queue), client/js/state.js (mirrors
  the server game by replaying events through the shared engine; stale updates dropped by

[Accounts & Friends] Google/Facebook sign-in, friends, profile photos, host lobby controls - COMPLETED
- New dependency (approved): the official `mongodb` driver. Accounts, sessions and
  friendships are stored in MongoDB when MONGODB_URI is set; without it an in-memory store
  with the same interface is used (accounts are lost on restart).
- Sign-in is optional. Guests play exactly as before with emoji avatars; friends need an account.
- Google sign-in (OAuth code flow with PKCE) and Facebook sign-in (code flow with
  appsecret_proof) using plain fetch, with no extra libraries. Configured only through environment
  variables. A button appears only when that provider's ID and secret are set.
- Sessions: random token in an HttpOnly, SameSite=Lax cookie (Secure on https), 30-day
  lifetime. Only a SHA-256 hash is stored, and sessions expire automatically via a TTL index. The
  WebSocket reads the same cookie when it connects. Signing in or out reconnects it.
- Friends: send/accept/decline/remove requests by 8-character friend code or name search;
  adding someone who already asked you accepts their request; limit of 200 friends.
  Live presence (Online / In lobby / Playing / Offline) and a request badge on the home
  screen. Facebook friends who also play show up as suggestions.
- Invites: from the lobby, invite an online friend; they get a popup with JOIN (or a toast
  if they are mid-game). Friends in a lobby show a JOIN button on the friends list.
  "+ Friend" / "Accept" buttons appear on other signed-in players' seats in the lobby.
- Profile photos and names: Google/Facebook photo in the home profile chip, settings,
  friends list, lobby seats, the in-game player panels (photo with a small colored pin
  badge) and the results podium. Only https photo URLs from Google/Facebook image hosts
  are accepted. Names from accounts can be up to 20 characters and are editable in Settings.
- Room creator (host) controls in the lobby: move any player or bot to another seat
  (swap), shuffle all seats randomly, set each seat's team (A/B) in team mode, add/remove
  bots, kick, and hand the host role to another connected player. Teams are now per seat
  instead of fixed by seat order; the game starts as long as each team has at least one player.
- Deploy: DEPLOY.md now covers MongoDB setup, Google and Facebook app registration
